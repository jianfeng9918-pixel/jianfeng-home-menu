# 剑锋家菜单 · V4

欢迎来家一起吃好吃的！

手机优先的家庭点菜网页，无需登录、不显示价格、不填写客人姓名。看菜单、加菜、统一写口味与忌口，最后复制点菜单，由客人自行粘贴到微信发送。网页不提交订单，也不自动发送消息。

## 当前菜单

- **80 道当前菜品**：50 道图卡、30 道文字卡，搭配简短口味或口感推荐语。套餐与跨分类展示会复用菜品，不能把各栏目数量相加作为总菜数。
- **6 道家里招牌**：酿蛋、卤水拼盘、豆豉蒸排骨、碌鹅、客家酿豆腐、客家土猪汤。招牌卡使用金色「招牌」徽章。
- 第二板块为 **10 道招牌套餐**，可以整套加入或单独挑选。补齐套餐时保留已选菜的做法和份数，只加入尚未选的菜。
- 提供全部入口及 10 个栏目：家里招牌、招牌套餐、客家经典、下饭肉菜、鸡肉与蛋、牛肉好菜、鱼虾海鲜、蔬菜小菜、热汤与粥、宵夜加点。
- 客家经典与其他栏目共用同一菜品 ID、已选数量与做法。宵夜包含毛豆、凉拌小菜、羊肉串（外卖）、凉拌小菜（外卖）、卤牛腱肉等；两种凉拌保留统称，外卖项明确标记。

## 点菜方式

页面不设搜索框，以栏目浏览和口味偏好帮助选择。偏好为「随心选」「偏清淡」「偏麻辣」「小孩爱吃」，使用固定标签筛选，不自动加菜。「小孩爱吃」仅是温和、软嫩或酸甜口味候选；具体辣度、忌口仍在点菜单中统一填写。

生菜、上海青、菠菜可选清炒或上汤；莴笋、荷兰豆、莲藕默认清炒。清蒸鱼可选择鲜鱼或鲈鱼，招牌套餐指定鲈鱼。同一道菜的不同做法分别记录，核对及复制时显示明确的菜名，例如「清炒生菜」「上汤生菜」「清蒸鲈鱼」。

菜品支持增加、减少和移除；底部显示所选条目数与总份数。同菜不同做法分行计数。选好后可统一写口味与忌口，也可补充一道菜单外想吃的菜。不再提供每道菜的独立备注。

空菜单不能复制；自动复制失败时展示完整可选中文本，支持长按或全选后手动复制。清空选择会移除已选菜及菜单外的菜，保留口味偏好与忌口。

## 本地保存与旧选择

选择仅保存在当前网页来源、当前浏览器的 `localStorage`，刷新后恢复。不同设备、不同浏览器或不同域名不会自动同步；清除浏览器数据可能丢失当前选择。无法保存时页面会提示先复制菜单。

`menu.js` 使用稳定 ID：80 道当前菜位于 `MENU.dishes`，29 道精简菜位于 `MENU.archivedDishes`。原菜单的 99 个 ID 全部保留，新增菜使用独立 ID；不要因排序或改名重新编号。旧选择中的归档菜仍可在点菜单里核对、调整和复制，但不出现在当前主菜单。

V4 使用 `{ id, variantId, quantity }` 记录选择，读取旧版按 ID 存储的份数并迁移到默认做法；旧版明确加入的完整套餐保留鲈鱼选择。符合旧版结构的单菜备注会并入统一口味与忌口。存储键继续使用 `jianfeng-home-menu:v1`，数据内容版本为 4。

## 文件与维护

| 文件 | 用途 |
| --- | --- |
| `index.html` | 网页结构、门头、菜单与点菜单弹层 |
| `styles.css` | 手机及电脑布局、图文卡片、按钮与交互状态 |
| `menu.js` | 当前及归档菜品、栏目、推荐语、口味标签、做法、套餐 |
| `images.js` | 菜品图片配置；通过菜品的 `imageKey` 对应 |
| `assets/` | 本地菜图及 `signature-badge.png` 招牌徽章 |
| `app.js` | 分类与偏好筛选、份数、做法、旧选择迁移、本地保存和复制 |
| `图片来源与许可.json` | 菜图来源及许可记录 |

菜品 `display` 为 `photo` 或 `text`；`recommendation` 用于显示短推荐语，`ingredients` 保留为资料字段。`variants` 定义做法，`defaultVariant` 定义默认项，`cartName` 决定核对及复制的名称。跨栏目引用同一 ID，套餐需指定做法时使用 `variantId`。

菜图为示意图，用户实拍优先替换。图片来源及权利独立于网页代码；来源记录中的 `unknown` 不代表开放许可。

## 静态部署

这是 HTML、CSS、JavaScript 静态网页，无需安装依赖或构建，无服务端接口、数据库或密钥。将本目录内容完整上传到静态托管目录，保留文件间相对路径即可。不要只上传 `index.html`；`menu.js`、`images.js`、`app.js`、`styles.css`、`assets/` 等资源需一起上传。

本地预览可在此目录运行：

```sh
python3 -m http.server 8080
```

再用浏览器打开 `http://localhost:8080/`。正式访问使用 HTTPS；自动复制不可用时仍有手动复制入口。

本项目 GitHub Pages 使用 `main` 分支根目录和 `.nojekyll`，推送后由 GitHub 发布。是否已更新以对应提交的 Pages 部署结果及线上页面为准。

## 微信访问验证边界

电脑浏览器、手机尺寸预览、模拟微信 User-Agent，以及 GitHub Pages 发布成功，都不能代替微信真机访问。本版仍需在手机微信内验证链接打开、图片加载、加减菜、做法选择、刷新恢复及复制流程；目前不能声称已完成微信真机验收。

GitHub Pages 域名的可访问性还取决于使用者网络和微信的实际处理。网页没有登录要求，但不保证任何网络或微信环境都能直接打开。网页不展示家庭地址或联系方式。
