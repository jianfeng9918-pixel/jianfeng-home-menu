# 剑锋家菜单 · V7

欢迎来家一起吃好吃的！

手机优先的家庭点菜网页，无需登录、不显示价格、不填写客人姓名。看菜单、加菜、统一写口味与忌口，最后复制点菜单，由客人自行粘贴到微信发送。网页不提交订单，也不自动发送消息。

## V7 视觉更新

浅玉绿加菜按钮、四等分口味选择器和手绘栏目横幅；保持菜单、字号、布局与点单逻辑。加菜按钮为「想吃这个 ＋」，选中后同宽显示加减数量，所有操作目标至少44×44px。主操作使用更醒目的鲜绿色，轻微按压反馈遵守系统“减少动态效果”偏好。

门头与十个栏目分别使用一张精致水粉风格的无字完整餐桌场景横幅，标题与说明保持为可编辑 HTML 文字。`presentation.js` 集中维护插画路径、20道重点菜推荐语、栏目说明及招牌章规格；`visual-v7.css` 管理V7展示。六道招牌的小章只显示「招牌」，小卡36px、手机大卡44px、电脑48px。

图片上的示意标签已移除，图片来源和生成记录集中保留在页面底部「图片来源」。各栏目连续衔接，删除「接着看看」及重复的栏目末尾核对按钮；通过左侧导航和固定底部「选好了」完成操作。

现有80道普通菜单、50图／30文、10个独立套餐选项以及菜图文件不变。V6的8张统一菜图继续使用。海鲜套餐用户照片和三份响应式文件均保持字节不变，展示比例仍为完整4:3。

横幅提供320／640px WebP，门头另有1280px版本；按显示尺寸选择；首屏优先，其余提前懒加载。装饰失败只隐藏图片，保留纯绿横幅和完整文字。生成提示、原图校验值和WebP信息见 `装饰生成记录.json`。

## 当前菜单

- **80 道唯一普通菜单菜品**：50 道图卡、30 道文字卡，搭配简短口味或口感推荐语。普通菜单中的跨栏目展示共用菜品选择，不会因卡片重复出现而重复加菜。另有 **10 个独立套餐选项**；套餐整桌图不计入普通菜单的 50 道图卡。
- **6 道家里招牌**：酿蛋、卤水拼盘、豆豉蒸排骨、碌鹅、客家酿豆腐、客家土猪汤。招牌卡使用金色「招牌」徽章。
- 第二板块为 **剑锋家招牌套餐（海鲜版）**，完整替换之前的十菜套餐。固定 10 道为：白灼九节虾、白灼花螺、蒜香排骨、卤水拼盘、凉拌菜、炒青菜、烧鹅、盐焗鸡爪、清蒸石斑、椰子鸡汤。
- 海鲜套餐可以整套加入或单独挑选。套餐选项使用独立 ID，即使与普通菜同名，也不共用数量；选了普通菜单中的卤水拼盘或椰子鸡汤，不会自动算作已选套餐项。补齐套餐只加入尚未选择的套餐项，并保留已有套餐份数。
- 取消「全部」入口，10 个栏目在同一页面依次展开：**家里招牌 → 招牌套餐 → 客家经典 → 下饭肉菜 → 鸡肉与蛋 → 牛肉好菜 → 鱼虾海鲜 → 蔬菜小菜 → 热汤与粥 → 宵夜加点**。
- 客家经典与其他栏目共用同一菜品 ID、已选数量与做法。宵夜包含毛豆、凉拌小菜、羊肉串（外卖）、凉拌小菜（外卖）、卤牛腱肉等；两种凉拌保留统称，外卖项明确标记。

## 点菜方式

页面不设搜索框，以连续浏览、栏目导航和口味偏好帮助选择。点击左侧栏目直接跳到对应区块；继续向下滚动时，栏目高亮随位置联动。栏目之间连续衔接，统一通过底部「选好了」查看已选菜单。跳转栏目保留页面中的菜卡与图片，不重新生成整个菜单。

偏好为「随心选」「偏清淡」「偏麻辣」「小孩爱吃」，使用固定标签筛选。筛选后，连续菜单会跳过没有匹配菜的栏目，相应导航不可点；招牌套餐仅在「随心选」时显示。改变偏好只调整浏览范围，不增加、移除或更改已经选好的菜。「小孩爱吃」仅是温和、软嫩或酸甜口味候选；具体辣度、忌口仍在点菜单中统一填写。

普通菜单中的生菜、上海青、菠菜可选清炒或上汤；莴笋、荷兰豆、莲藕默认清炒。普通清蒸鱼可选择鲜鱼或鲈鱼；海鲜套餐中的「清蒸石斑」是独立选项，不会改动普通清蒸鱼的鱼种或数量。同一道普通菜的不同做法分别记录，核对及复制时显示明确的菜名，例如「清炒生菜」「上汤生菜」「清蒸鲈鱼」。

菜品支持增加、减少和移除；底部显示所选条目数与总份数。同菜不同做法分行计数。选好后可统一写口味与忌口，也可补充一道菜单外想吃的菜。不再提供每道菜的独立备注。

空菜单不能复制；自动复制失败时展示完整可选中文本，支持长按或全选后手动复制。清空选择会移除已选菜及菜单外的菜，保留口味偏好与忌口。

## 本地保存与旧选择

选择仅保存在当前网页来源、当前浏览器的 `localStorage`，刷新后恢复。不同设备、不同浏览器或不同域名不会自动同步；清除浏览器数据可能丢失当前选择。无法保存时页面会提示先复制菜单。

`menu.js` 使用稳定 ID：80 道普通菜单菜品位于 `MENU.dishes`，29 道精简菜位于 `MENU.archivedDishes`。原菜单的 99 个 ID 全部保留；海鲜套餐另外维护 10 个独立选项 ID。不要因排序或改名重新编号，也不要将套餐 ID 与同名普通菜合并。旧选择中的归档菜仍可在点菜单里核对、调整和复制，但不出现在当前主菜单。

V5 沿用 `{ id, variantId, quantity }` 选择格式，读取旧版按 ID 存储的份数并迁移到默认做法。旧十菜套餐的页面入口已经替换，但历史选择中的普通菜 ID、份数与已有做法继续保留，不自动改成新海鲜套餐选项。符合旧版结构的单菜备注会并入统一口味与忌口。存储键继续使用 `jianfeng-home-menu:v1`，不因本次页面或套餐升级重置选择。

## 文件与维护

| 文件 | 用途 |
| --- | --- |
| `index.html` | 网页结构、门头、菜单与点菜单弹层 |
| `styles.css` / `visual-v6.css` / `visual-v7.css` | 基础布局与 V6/V7 视觉层、手机及电脑卡片、按钮与交互状态 |
| `presentation.js` | 十个栏目说明、插画路径、招牌角标规格、20 道重点菜文案 |
| `menu.js` | 当前及归档菜品、栏目、推荐语、口味标签、做法、套餐 |
| `images.js` | 菜品图片配置；通过菜品的 `imageKey` 对应 |
| `image-sizes.js` | 图片的尺寸与多分辨率 `srcset` 映射 |
| `assets/` | 本地菜图、V7 十一张完整手绘横幅与浅金招牌底章 |
| `assets/responsive/` | 适合不同显示尺寸的图片版本 |
| `app.js` | 连续栏目、锚点跳转与滚动联动、偏好筛选、图片加载、份数、做法、旧选择迁移、本地保存和复制 |
| `图片来源与许可.json` | 菜图来源及许可记录 |

普通菜品 `display` 为 `photo` 或 `text`；`recommendation` 用于显示短推荐语，`ingredients` 保留为资料字段。`variants` 定义做法，`defaultVariant` 定义默认项，`cartName` 决定核对及复制的名称。普通菜单跨栏目引用同一 ID；海鲜套餐使用独立 ID，并通过套餐清单维护名称和选择关系。

## 图片与加载

酿蛋现用完整一盘客家蛋皮包肉的 ImageGen 示意图，根据原有菜品形态参考生成，来源记录在底部集中展示。海鲜套餐整桌图改用用户上传的家宴原照片，不使用生成图。

此前生成的旧十菜套餐整桌图仅保留在本地预览输出中供查看，没有用于当前网页。普通菜单图卡数量仍为 50；套餐整桌照片是独立展示资产，不参与这一统计。

`image-sizes.js` 与 `assets/responsive/` 提供多尺寸图片，浏览器按显示宽度选择合适资源；加载失败时回退到原图路径。首张招牌图优先加载，其他菜图在距离视口约 1200px 时提前请求；点击栏目时也会提前请求目标区块前几张图。较旧浏览器不支持提前观察时保留原生图片加载方式。

加减菜和选择做法只更新按钮、数量与文字，栏目跳转只调整滚动位置，均保留已有图片节点；改变口味偏好时才按新的展示范围重新生成菜单。

普通菜单中的网图和生成图保留来源与生成记录，用户实拍优先替换；套餐整桌图来源为用户提供的照片。图片来源及权利独立于网页代码，记录见 `图片来源与许可.json`；来源中的 `unknown` 不代表开放许可。

## 静态部署

这是 HTML、CSS、JavaScript 静态网页，无需安装依赖或构建，无服务端接口、数据库或密钥。将本目录内容完整上传到静态托管目录，保留文件间相对路径即可。不要只上传 `index.html`；`menu.js`、`presentation.js`、`images.js`、`image-sizes.js`、`app.js`、`styles.css`、`visual-v6.css`、`visual-v7.css`、`装饰生成记录.json`、整个 `assets/`（含 `responsive/`）等资源需一起上传。

本地预览可在此目录运行：

```sh
python3 -m http.server 8080
```

再用浏览器打开 `http://localhost:8080/`。正式访问使用 HTTPS；自动复制不可用时仍有手动复制入口。

本项目 GitHub Pages 使用 `main` 分支根目录和 `.nojekyll`，推送后由 GitHub 发布。是否已更新以对应提交的 Pages 部署结果及线上页面为准。
